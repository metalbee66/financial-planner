# Family Planner — Changelog

## v2.0.0 (in progress) — Modular monolith + Projects module

Rebranding "Financial Planner" → "Family Planner" and restructuring the app into a modular monolith. The existing finance features become the **Finance** module; a new **Projects** module (Asana-like project management) is added alongside. Future modules slot into the same registry. See [tasks/plan.md](tasks/plan.md) for the full plan.

### Phase 3 — Task Richness (in progress, 2026-05-04)

- **Task 3.1** — Task dependencies + cycle detection: four pure helpers in `data.js` — `wouldCreateCycle` (DFS from candidate dep, treats deleted tasks as leaves so phantom cycles don't trigger), `addDependency` and `removeDependency` (immutable, same-ref no-ops for self-dep, duplicates, missing target, and cycle attempts), `countBlockingDeps` (counts deps that exist in the list and aren't `done`). The task panel gets a Dependencies section (works on top-level and subtask panels) with a same-project picker, inline error line, and a list showing each prerequisite's name + status pill + × to remove. Cycle attempts surface a clear "would create a cycle" error rather than being silently filtered. Task rows render an `⛔ Blocked by N` pill next to the name when there are unmet deps; clears automatically when the prerequisite is marked done or the dep is removed. 16 new pure-data unit tests (52 total); 5 new Playwright tests (29 total). (commit `116db1e`)
- **Task 3.2** — Comments thread (append-only): two pure helpers in `data.js` — `createComment` (id `c_…`, trims text, defaults blank author to `'anonymous'`) and `addCommentToTask` (immutable append, bumps `updatedAt`, same-ref no-op when target task is missing). Task panel gets a Comments section between subtasks and meta with chronological list (oldest first, newest at bottom — matches the audit-trail ordering called for in plan §3.2), per-comment author + relative-time pill (hover for absolute timestamp), and a textarea composer. Empty/whitespace-only input rejected with inline error; Ctrl/Cmd+Enter posts. Author derives from `currentUser.email` when signed into Firebase, else falls back to `'anonymous'`. No edit/delete UI by design — comments are part of the audit trail. 8 new pure-data unit tests (60 total); 5 new Playwright tests (34 total).
- **Task 3.3** — Activity / audit-trail feed: three pure helpers in `data.js` — `createEvent` (id `e_…`, fields `{kind, by, at, before, after}`, anonymous fallback like comments), `addEventToTask` (immutable append, same-ref no-op when target task is missing), and `taskPatchEvents` (diffs a patch over the audit-tracked subset `{status, assignee, dueDate}` and returns one event per actual change). UI side rolls every task mutation through new `applyTaskPatch` / `applyAddDependency` / `applyRemoveDependency` helpers in `index.js` so audit logging is automatic — three call sites (inline status dropdown, subtask status dropdown, panel save) and the dep section's add/remove buttons. The Comments section becomes a single combined "Activity" feed: comments and events are merged and sorted by timestamp ascending, so the newest entry sits at the bottom right above the composer. Events render with kind-specific icons + a humanised summary that resolves dep-id references to current task names (and falls back to "a deleted task" if the prerequisite is gone). Untracked field changes (name, description, priority, startDate) deliberately produce no events. 13 new pure-data unit tests (73 total); 6 new Playwright tests (40 total). Phase 3.2's `#tp-comments-section` rename to `#tp-activity-section` is propagated through the one e2e test that referenced it.
- **Task 3.4** — File attachments (inline ≤500 KB + URL refs): seven pure helpers in `data.js` — `createFileAttachment` / `createUrlAttachment` (id `a_…`, kind `'file'`/`'url'`), matching `validateFileAttachment` / `validateUrlAttachment` (validators check size cap, dataUri presence, http(s) scheme), `addAttachmentToTask` / `removeAttachmentFromTask` (immutable, same-ref no-ops), `taskAttachmentSize` (sums inline-file bytes, URL refs contribute zero), plus a shared `formatBytes`. Constants `MAX_INLINE_ATTACHMENT_SIZE = 500 KB` and `TASK_ATTACHMENT_WARN_SIZE = 1 MB`. New Attachments section in the task panel between deps and subtasks: drag-drop zone + file picker for inline files (rejected at the input boundary if oversize, with explicit size message), `<details>`-wrapped URL form (title + URL), chip list with `<a download>` for inline files and `<a target="_blank" rel="noopener noreferrer">` for URLs, × remove with confirm. Soft warning banner appears when cumulative inline-file bytes on a task exceed 1 MB. Add and remove flow through new `applyAddAttachment` / `applyRemoveAttachment` UI helpers so `attachment_added` and `attachment_removed` events log into the activity feed alongside the existing event kinds. 17 new pure-data unit tests (90 total); 7 new Playwright tests (47 total) including a real `setInputFiles` round-trip with a 600 KB buffer to exercise the oversize rejection path.
- **Task 3.5** — Milestone flag: `isMilestone: false` field added to the task schema (sanitised + create-time defaults handled). Task panel gets a checkbox toggle ("Mark as milestone" with a ◆ glyph next to the label) saved on panel save. Milestone task rows pick up a `task-row-milestone` class with a soft accent-coloured highlight on the row plus a leading ◆ glyph in the task name. The per-project task list header gains a "◆ Milestones only" filter checkbox; checking it hides non-milestones (it preserves any non-milestone parent of a milestone subtask so the indented render stays anchored). Filter state lives on `mode.taskFilters` and resets when navigating to a different project. No audit-event logging on the toggle — milestone changes aren't in plan §3.3's tracked-mutation list. 7 new pure-data unit tests (97 total); 4 new Playwright tests (51 total). Note for Phase 4: timeline (4.2) and calendar (4.3) need to render the diamond glyph on milestone tasks too — wiring deferred until those views are built.

### Phase 4 — Per-Project Views (in progress, 2026-05-07)

- **Task 4.1** — List view (sort, group, filter): three new pure helpers in `data.js` — `sortTasks` (by `dueDate`/`name`/`priority` × `asc`/`desc`, missing dueDate always last regardless of direction, `createdAt` tiebreaker), `filterTasks` (assignee + status + milestonesOnly with AND semantics; non-matching parent kept when one of its subtasks matches so the indented render isn't orphaned), `groupTopLevelTasks` (`none`/`status`/`assignee`; status uses canonical TASK_STATUSES order, assignee uses brad → diana → others alphabetically → unassigned, empty buckets dropped). The legacy `applyTaskFilters` from `index.js` is replaced by the generalised `filterTasks` so milestonesOnly behavior is unchanged. New toolbar above the task list with sort-by dropdown + direction toggle button, group-by dropdown, assignee filter, status filter (existing milestones-only checkbox preserved). When grouping, section headers (`.tasks-group-header`) appear between buckets with `Label · count`. Subtasks always travel with their parent's bucket regardless of group/sort — they're never bucketed independently. Done top-level tasks stay pinned to the bottom of their bucket sorted by `completedAt` desc, preserving the Phase 2.1 UX. Sort/group/filter state lives on `mode.taskSort` / `mode.taskGroup` / `mode.taskFilters` and resets together when navigating to a different project. Empty-state text now distinguishes "no tasks at all" from "no tasks match these filters". 22 new pure-data unit tests (119 total); 11 new Playwright tests (62 total). Server-side: `app/server.py` switched from single-threaded `TCPServer` to `ThreadingHTTPServer` to fix the long-standing `ERR_CONNECTION_REFUSED` / `ERR_ABORTED` flake under fast-fire ES-module asset load.
- **Task 4.2** — Timeline view (Gantt-style, month zoom + dependency arrows + milestones): two new pure helpers in `data.js` — `computeTimelineRange` (returns `{startDate, endDate, totalDays, months[]}` from min/max task dates with 14-day padding snapped to month boundaries; `null` when no task has any usable date), `computeTaskBars` (per-task `{leftPct, widthPct, days, isMilestone, …}` derived from a precomputed range; tasks with only one of start/due become 1-day bars; tasks with neither are excluded). Project detail view gets a `.view-tabs` strip ("List" | "Timeline") above the task body; toolbar (sort/group/filter) is now scoped to the list view only. Active view persists on same-project re-entry but resets to List when navigating to a different project. Timeline UI: month-axis header (each month a `.timeline-axis-month` slice positioned by leftPct/widthPct), one row per scheduled task with a 200 px label gutter + flex track holding the bar, status-coloured `.timeline-bar` buttons (rgba palette mirrors the list-view status pills), click bar → opens existing `openTaskPanel`. Milestones render as `.timeline-milestone` (rotated diamond glyph centered on the date with translateX(-50%)) instead of bars — gold by default, green when done, red when blocked. Dependency arrows render as a single SVG overlay (`.timeline-arrows`) inside the rows track region with one dashed `<line class="timeline-arrow">` per dep, using mixed-units coordinates (x in `%`, y in px) so arrows reflow with the chart. Tasks with no dates surface as a `.timeline-unscheduled` count below the chart; full empty-state when no task has any dates. 12 new pure-data unit tests (131 total); 10 new Playwright tests (72 total).
- **Task 4.3** — Calendar view (month grid): two new pure helpers in `data.js` — `getMonthGridCells(year, month, todayIso)` (Monday-first 7-col grid, returns multiple-of-7 cells with `{date, day, inMonth, isToday, weekday}`; pads leading/trailing weeks with surrounding-month days), `bucketCalendarTasks(tasks)` (returns `Map<dateIso, [{task, kind}]>`; multi-day task → `due` pill on `dueDate` + dimmer `start` pill on `startDate`; single-day or sole-date task → one `due` pill; date-less tasks excluded). New `Calendar` tab joins the existing List/Timeline tabs as the third project view. Layout: a header bar (`< [Month YYYY] >` + `Today` button) + Mon..Sun weekday header + 7×N grid of `.cal-day` cells; cells have `.cal-day-number` + `.cal-pills` stack of status-coloured `.cal-pill`s (`.cal-pill-start` is the dimmer italicised variant). Today cell gets `.is-today` (subtle accent fill); out-of-month pad cells get `.is-outside`. Clicking a pill opens the task panel directly (`stopPropagation` so the cell click doesn't also fire); clicking elsewhere on a cell toggles a `.cal-day-popover` listing every pill on that date — each item links into the task panel. Prev/Next/Today nav buttons mutate `mode.calendarYear` / `mode.calendarMonth` and re-render; state persists on same-project re-entry, resets to today on project switch. 13 new pure-data unit tests (144 total); 9 new Playwright tests (81 total). Dev-server tweak: `server.py` now respects `FAMILY_PLANNER_NO_BROWSER=1` to suppress the auto-open browser tab; `playwright.config.js` sets it on `webServer.env` so test runs no longer spawn a fresh browser window each time.

### Phase 5 — Cross-Project Views (in progress, 2026-05-08)

- **Task 5.1** — Overview tab (cross-project cards): three new pure helpers in `data.js` — `computeProjectProgress` (done/total/percent across a project's full task tree, subtasks included; empty projects report 0%/0/0 instead of NaN), `countOverdueTasks` (per-project count of `dueDate < today` non-done tasks), `findNextMilestone` (earliest non-done milestone with a `dueDate` ≥ today, falling back to the earliest past milestone if every milestone is overdue) — plus `sortProjectsForOverview` driving a new `Sort` selector with `updated`/`status`/`dueDate`/`percent` modes (name as universal tiebreaker; empty/0% projects sort to end under percent so they don't masquerade as 0% done). Project cards add a progress bar (% complete + done/total) and a flags row (◆ next milestone date, ⚠ N overdue) below the description. Sort persists on the list mode so clicking into a project and back preserves ordering. 13 new pure-data unit tests (157 total); 6 new Playwright tests (87 total).
- **Task 5.2** — My Tasks (per-user summary tab): three new pure helpers in `data.js` — `bucketTasksForUser(tasks, userId, todayIso)` returns `{overdue, thisWeek, upcoming, completed}` (overdue = `dueDate < today` not done; thisWeek = today through today+6 days; upcoming = dueDate > today+6 OR no dueDate; completed = `status === 'done'`; sorted by dueDate asc within bucket, completed by completedAt desc with updatedAt fallback), `defaultMyTasksUser(email)` (maps `metalbee66@gmail.com` → `brad`, `dianaleshcheva@gmail.com` → `diana`, falls back to `brad` for unknown/empty emails), `collectMyTasksUserOptions(tasks)` (always brad+diana first, then external assignees alphabetically, deduped). The Projects list view now has sub-tabs **Overview** | **My Tasks**. The My Tasks view shows a user dropdown (default = current Firebase user mapped to brad/diana, else brad) and four sections — Overdue, Due this week, Upcoming, Completed (collapsed by default, click header to toggle). Each row shows project name + task name (with ◆ for milestones, strikethrough when done) + due date + status badge; click or Enter opens the existing task panel directly (cross-project nav). Empty state when the selected user has no tasks anywhere. Sub-tab + selected user + collapse state persist across navigation back from a project. 11 new pure-data unit tests (168 total); 8 new Playwright tests (95 total).
- **Task 5.3** — Dashboard tab (cross-project metrics + completion bar chart): two new pure helpers in `data.js` — `computeDashboardMetrics(projects, tasks, todayIso)` produces the six headline numbers (`activeProjects` = status `'active'` and not archived; `openTasks` = non-done across all projects; `overdueTasks` = dueDate < today, not done, undated excluded; `dueThisWeek` = today through today+6 inclusive; `completedLast30Days` = `status === 'done'` with completedAt within today-30..today inclusive; `upcomingMilestones` = milestone, not done, dueDate today through today+13), and `computeWeeklyCompletionBars(tasks, todayIso, weeks=8)` returns rolling 7-day buckets in chronological order (oldest first, newest last) with the count of tasks completed per bucket. Plus a `DASHBOARD_WEEKS` constant. The Projects list view gains a third sub-tab **Dashboard** alongside Overview/My Tasks. UI: a six-card grid (CSS auto-fit, 160 px min) where each card is `data-metric="<key>"` with a large monospace value + label; the Overdue card flips red (`dashboard-card-flag`) when count > 0. Below the cards, an inline-SVG bar chart ("Tasks completed per week — Last 8 weeks") with `viewBox="0 0 400 120"` so it scales to container width; bars are accent-coloured with hover `<title>` tooltips, value labels above non-zero bars, and bucket-start date labels along the x-axis. Auto-refresh comes for free via the existing Firebase listener — every state change re-renders the module. 14 new pure-data unit tests (182 total); 10 new Playwright tests (105 total).
- **Task 5.4** — Files summary by project (cross-project attachments view): one new pure helper in `data.js` — `collectAttachmentsByProject(projects, tasks)` flattens every task's `attachments[]` into one project-grouped list, returning `[{projectId, projectName, items: [{attachment, taskId, taskName}]}]`. Groups sorted by project name (case-insensitive); within each group items sorted by `addedAt` desc so the freshest uploads sit at the top. Projects with no attachments and orphaned tasks (whose project no longer exists) are dropped. The Projects list view gains a fourth sub-tab **Files** alongside Overview/My Tasks/Dashboard. UI: a per-project `.files-group` card with a header (name + count badge) and a 6-column table (Task / Name / Type / Size / Added by / Added on); rows are keyboard-focusable and click/Enter opens the source task panel directly (cross-project nav, same pattern as My Tasks). Inline files render type "File" + human-readable size; URL refs render type "URL" + size dash. Empty state when no project has any attachments. 8 new pure-data unit tests (190 total); 7 new Playwright tests (112 total).
